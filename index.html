01 · Definition

What is CUDA?

CUDA (Compute Unified Device Architecture) is a parallel computing platform and programming model created by NVIDIA.

It lets developers use the GPU, originally built for graphics, as a general-purpose processor (GPGPU) that accelerates heavy computations.

  • Runs on NVIDIA GPUs (GeForce, RTX, Tesla, A100, H100, Blackwell)
  • Extends C and C++ with keywords for kernels, memory and threads
  • Usable from Python (CuPy, Numba, PyTorch) and Fortran
  • Free toolkit: nvcc compiler, runtime, libraries and profilers

Software stack

02 · History

History of CUDA

  1. 2003

    Brook for GPUs

    Stanford researchers (led by Ian Buck) show that GPUs can run general-purpose computations through a streaming language.

  2. 2006

    G80 and CUDA announced

    NVIDIA GeForce 8800 GTX introduces a unified shader architecture. CUDA is announced alongside it.

  3. 2007

    CUDA 1.0

    First public toolkit with the nvcc compiler and a C-like language for writing GPU kernels.

  4. 2008

    Tesla GPUs

    Dedicated compute GPUs for scientific computing and high-performance computing (HPC) clusters.

  5. 2009

    OpenCL appears

    The Khronos Group releases OpenCL, an open, multi-vendor standard for heterogeneous parallel computing.

  1. 2010

    Fermi architecture

    Adds ECC memory, L1 and L2 caches and much stronger double-precision performance for HPC.

  2. 2012

    AlexNet on CUDA

    A deep CNN is trained on two GTX 580 GPUs with CUDA, starting the modern deep learning era.

  3. 2014

    cuDNN released

    Deep learning primitives adopted by Caffe, Torch and later TensorFlow and PyTorch.

  4. 2017

    Volta and Tensor Cores

    Dedicated matrix-multiply units (Tensor Cores) accelerate AI training and inference.

  5. 2020-2024

    Ampere, Hopper, Blackwell

    A100, H100 and B200 GPUs push transformer and large language model acceleration further.

CUDA's success came from pairing GPU hardware innovation (Tensor Cores, HBM memory) with a mature software ecosystem.

GPU: thousands of small cores

Each small square = one CUDA core (illustrative).

CPU: latency-oriented

  • A few powerful cores (typically 4 to 64)
  • Large caches and sophisticated branch prediction
  • Excellent for sequential tasks, OS work and complex logic

GPU: throughput-oriented

  • Thousands of simpler cores grouped into SMs
  • Hides memory delay by switching between many threads
  • Excellent for data-parallel work: matrices, images, neural networks

04 · CUDA Architecture

Hardware Architecture

GPU die (simplified)

Each small block = Streaming Multiprocessor (SM). Green squares = CUDA core groups. Not to scale.

Inside one Streaming Multiprocessor

FP32 / INT32 cores

Execute arithmetic, one operation per thread.

Tensor cores

Matrix multiply-accumulate units that accelerate AI.

Warp schedulers

Issue one instruction to a group of 32 threads (a warp).

Register file

Fastest private storage, one slice per thread.

Shared memory and L1

Programmable on-chip memory shared by a block.

Load/Store and SFU

Memory access units and special math (sin, rsqrt).

SIMT execution: threads are grouped into warps of 32. All threads in a warp run the same instruction on different data.

04 · CUDA Architecture

CUDA Memory Hierarchy

Registers per threadabout 1 cycle
Shared memory per blockabout 20-30 cycles
L1 / L2 cache per SM / whole GPUabout 30 / 200 cycles
Global memory (VRAM / HBM) whole GPUabout 400-800 cycles
Host RAM (over PCIe) CPU sidemicroseconds and up

Faster and smaller at the top; larger and slower at the bottom. Latencies are approximate, in GPU clock cycles.

Why it matters

Most CUDA tuning moves data into faster memory: coalesced global memory access, tiling in shared memory, and avoiding slow PCIe transfers.

Rule of thumb

Keep data on the GPU as long as possible and reuse it many times before writing results back.

Scope

Each memory level is visible to a different set of threads: a thread, a block, or the whole grid.

05 · How CUDA Works

            
Example: Vector Addition in CUDA

          

        

        

          

            

              
vector_add.cu

              
#include <stdio.h>
#include <cuda_runtime.h>

// Kernel: runs on the GPU, one thread per array element
__global__ void vectorAdd(const float *a, const float *b, float *c, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;   // global thread index
    if (i < n) c[i] = a[i] + b[i];
}

int main() {
    const int n = 1 << 20;                        // 1,048,576 elements
    size_t bytes = n * sizeof(float);

    // 1) Host (CPU) buffers
    float *h_a = (float*)malloc(bytes);
    float *h_b = (float*)malloc(bytes);
    float *h_c = (float*)malloc(bytes);
    for (int i = 0; i < n; i++) { h_a[i] = 1.0f; h_b[i] = 2.0f; }

    // 2) Device (GPU) buffers
    float *d_a, *d_b, *d_c;
    cudaMalloc(&d_a, bytes);
    cudaMalloc(&d_b, bytes);
    cudaMalloc(&d_c, bytes);

    // 3) Copy inputs CPU to GPU
    cudaMemcpy(d_a, h_a, bytes, cudaMemcpyHostToDevice);
    cudaMemcpy(d_b, h_b, bytes, cudaMemcpyHostToDevice);

    // 4) Launch kernel: 4096 blocks x 256 threads
    int threads = 256;
    int blocks  = (n + threads - 1) / threads;
    vectorAdd<<<blocks, threads>>>(d_a, d_b, d_c, n);

    // 5) Copy result GPU to CPU and clean up
    cudaMemcpy(h_c, d_c, bytes, cudaMemcpyDeviceToHost);
    printf("c[0] = %f\n", h_c[0]);               // expected: 3.000000

    cudaFree(d_a); cudaFree(d_b); cudaFree(d_c);
    free(h_a); free(h_b); free(h_c);
    return 0;
}

            

            

              
terminal

              
nvcc vector_add.cu -o vector_add
./vector_add

            

          

          

            

              
__global__

              
Marks a kernel: a function called from the CPU and executed on the GPU.

            

            

              
<<<blocks, threads>>>

              
The execution configuration: how many blocks and threads run the kernel.

            

            

              
Built-in indices

              
blockIdx, blockDim and threadIdx give each thread its unique position in the data.
              

            

            

              
Memory API

              
cudaMalloc, cudaMemcpy and cudaFree mirror C's malloc, memcpy and free, but for
                GPU memory.

            

          

        

      


      
      

        

          

            
06 · CUDA-X Libraries

            
Popular CUDA Libraries

          

        

        

          

            

              
cuBLAS

              
GPU-accelerated Basic Linear Algebra Subprograms: fast matrix and vector operations.

            

            

              
cuFFT

              
Fast Fourier Transforms for signal processing, imaging and scientific simulation.

            

            

              
cuDNN

              
Deep neural network primitives (convolution, attention, normalization). Used by PyTorch and TensorFlow.
              

            

            

              
cuSPARSE

              
Operations on sparse matrices, common in graphs, physics and recommender systems.

            

            

              
cuSOLVER

              
Dense and sparse direct solvers, eigenvalues and matrix factorizations.

            

            

              
cuRAND

              
High-throughput random number generation for Monte Carlo and simulation.

            

            

              
Thrust

              
C++ parallel algorithms (sort, scan, reduce) with an STL-like interface.

            

            

              
NCCL

              
Multi-GPU and multi-node collective communication (all-reduce, broadcast) for training.

            

            

              
TensorRT

              
Optimizer and runtime that makes trained deep learning models fast for inference.

            

          

          
Most deep learning frameworks (PyTorch, TensorFlow, JAX) call these
            libraries under the hood.

        

      


      
      

        

          

            
07 · Alternatives

            
Alternatives to CUDA

          

        

        

          

            

              
OpenCL (Khronos, 2009)

              
Open standard running on CPUs, GPUs and FPGAs from many vendors. Portable but more verbose.

            

            

              
AMD ROCm / HIP

              
Open-source GPU platform for AMD. HIP has CUDA-like C++ syntax, and hipify translates CUDA code.

            

            

              
SYCL / Intel oneAPI (DPC++)

              
Single-source modern C++ for heterogeneous hardware, with backends for Intel, NVIDIA and AMD.

            

            

              
Vulkan Compute / DirectCompute

              
Compute shaders built on graphics APIs. Cross-platform, closely tied to graphics pipelines.

            

            

              
OpenACC / OpenMP offload

              
Directive-based: pragmas on loops let the compiler generate GPU code. Less effort, less control.

            

            

              
OpenAI Triton

              
Python-based language for writing tiled GPU kernels, targeting NVIDIA and AMD GPUs.

            

            

              
Apple Metal

              
Apple's low-level GPU API for macOS and iOS devices, including Apple silicon.

08 · Assessment

            
Advantages of CUDA

          

        

        

          

            

              
Massive parallel speed

              
Thousands of cores execute data-parallel work; often 10 to 100 times faster than CPUs on suitable
                workloads.

            

            

              
Rich library ecosystem

              
cuBLAS, cuDNN, NCCL and more give near-peak performance without low-level code.

            

            

              
Mature tooling

              
Nsight Systems and Compute profilers, cuda-gdb debugger and compute-sanitizer for memory errors.

            

            

              
Documentation and community

              
Extensive official guides, textbooks, courses and a very large developer community.

            

            

              
Fine-grained control

              
Direct access to the memory hierarchy, warps, streams and Tensor Cores for expert tuning.

            

            

              
Scales out

              
NVLink, multi-GPU programming and NCCL scale applications from one GPU to large clusters.

            

          

          
Result: CUDA is the default platform for deep learning and HPC on NVIDIA hardware.

        

      


      
      

        

          

            
08 · Assessment

            
Limitations of CUDA

          

        

        

          

            

              
Vendor lock-in

              
Runs only on NVIDIA GPUs. Code is not portable to AMD or Intel hardware.

            

            

              
Steep learning curve

              
Developers must understand threads, blocks, warps, memory spaces and synchronization.

            

            

              
Data-transfer overhead

              
Moving data between CPU and GPU over PCIe is slow and can erase the speedup.

            

            

              
Not for every workload

              
Branch-heavy or irregular code causes warp divergence and idle threads.

            

            

              
Memory, cost and power

              
Limited VRAM for very large models. High-end GPUs are expensive and power-hungry.

            

            

              
Hard to debug

              
Race conditions and asynchronous execution make parallel bugs difficult to find.

09 · Conclusion

            
Conclusion

          

        

        

          
    
            
  • CUDA turned the GPU from a graphics chip into a general-purpose parallel processor.
    • 
            
  • Its core model (kernels, threads, blocks and the memory hierarchy) maps well to data-parallel
              problems.
    • 
            
  • A rich library ecosystem (cuBLAS, cuDNN, NCCL) made CUDA the backbone of modern AI and HPC.
    • 
            
  • The main trade-off is performance and maturity versus vendor lock-in.
    • 
            
  • Open alternatives (OpenCL, SYCL, ROCm/HIP, Triton) are growing and are worth evaluating for portability.
            
    • 
          

          

            
Key takeaway

            
CUDA made the GPU a general-purpose parallel computer, and it became the foundation of
              modern AI and scientific computing.
